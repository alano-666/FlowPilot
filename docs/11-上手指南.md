# FlowPilot 上手指南（V1.1）

> 面向使用者：从零到跑通「飞书群消息 → AI 分析 → 看板跟踪」完整闭环。
> 全部操作在网页完成，无需编程知识。

## 一、快速了解（30 秒）

FlowPilot 做三件事：
1. **读文档**：上传业务流程文档（Word/PDF/Markdown），AI 自动拆解成流程模板
2. **听聊天**：接入飞书群、微信导出文件、邮箱邮件，AI 从沟通记录里判断项目走到哪一步
3. **看进度**：一个看板展示所有项目的节点、进度、干系人、风险，一键联系责任人

## 二、登录与界面

1. 打开 http://localhost:8080（部署地址以实际为准）
2. 账号 `admin` / 密码 `admin123`（管理员可改，系统设置里可给同事开账号）
3. 左侧 4 个菜单：

| 菜单 | 干什么 |
|---|---|
| 📊 项目看板 | 所有项目卡片墙：进度条、风险色、渠道接入状态、新建项目 |
| 📚 流程模板 | 上传文档让 AI 建模、编辑模板、发布、复制、删除 |
| 🔌 数据源管理 | 飞书接入向导、微信导入、邮箱配置、项目渠道绑定 |
| ⚙️ 系统设置 | 用户管理、运行配置 |

## 三、核心操作流程（跟着做一遍）

### 第 1 步：创建流程模板（5 分钟）

1. 进入「流程模板」→ 点「📄 上传文档 AI 建模」
2. 上传你的流程文档（支持 Word/PDF/Markdown/TXT；没有文档就点「📋 粘贴文本建模」，
   把流程步骤粘贴进去，示例见 docs/examples/星辰电商订单中心升级项目实施流程（精简版）.md）
3. AI 自动抽取：流程名、每个节点的完成标准、责任角色、SLA 时效、分支规则、专业词库
4. 弹出的草稿页人工核对 → 点「保存并发布」
5. 模板进入「已发布」状态，可以被项目使用

> 💡 AI 建模质量取决于文档写得清不清楚：每个步骤写清"完成标准"和"谁负责"，AI 识别最准。

### 第 2 步：接入飞书群（一次性，约 15 分钟）

完整图文步骤见 docs/07-飞书接入指南.md，精简版：

1. 飞书开发者后台创建企业自建应用（添加机器人能力）
2. 开通权限（批量导入）：
```json
{
  "scopes": {
    "tenant": [
      "contact:user.base:readonly",
      "im:chat:read",
      "im:message.group_msg",
      "im:message.group_msg:readonly",
      "im:message.group_at_msg:readonly",
      "im:message.p2p_msg:readonly",
      "im:message:send_as_bot",
      "im:message:readonly"
    ],
    "user": []
  }
}
```
3. 事件订阅 `im.message.receive_v1`，回调地址 `https://你的公网地址/api/v1/webhooks/feishu/events`
   （没有域名用 `./scripts/tunnel.sh` 内网穿透，脚本会直接打印要填的地址）
4. **发布版本**（最容易漏的一步）
5. App ID / App Secret 填入 `.env.local` → 重启 → 数据源管理页点「🔍 检测飞书凭证」
6. 把机器人拉进项目群

### 第 3 步：接入微信导入与邮箱（可选，各 5 分钟）

**微信导入**（个人微信无官方接口，走文件导入）：
- 微信电脑版复制聊天记录 → 存成 .txt → 扔进 `data/watch/` 文件夹
- 系统自动解析 → 按文件名匹配项目 → 触发 AI 分析（教程见 docs/examples/微信聊天记录导出教程.md）

**邮箱**（163/QQ/企业邮箱均可）：
- 邮箱设置里开启 IMAP 并生成「授权码」
- `.env.local` 填 6 行（`FLOWPILOT_EMAIL_*`，教程见 docs/examples/邮箱接入与邮件剧本.md）
- 重启后每 15 分钟自动拉取最近 14 天邮件，主题/发件人匹配项目自动归入

### 第 4 步：创建项目并绑定群（3 分钟）

1. 看板 → 「＋ 新建项目」→ 填项目名/客户名 → 选已发布的流程模板
2. 数据源管理 → 「项目渠道矩阵」→ 选项目 → 选飞书组织 → 下拉直选机器人所在群 → 绑定
   （一个项目可绑**多个群**；微信/邮件按项目名自动归属，无需手动绑）

### 第 5 步：让系统开始跟踪（持续）

- 群里任何人发消息 → **秒级**进入项目详情「最近消息」（事件实时推送）
- 点「🤖 立即 AI 分析」（或等 30 分钟定时任务）→ AI 判断：
  - 当前节点推进到哪里、完成百分比
  - 谁在负责（干系人自动识别，含真实联系方式）
  - 有没有风险（预警/卡顿，直接显示在卡片上）
  - 下一步该做什么
- 节点超时（SLA）→ 系统自动在群里 @ 责任人

### 第 6 步：人工校准（AI 判断不准时）

1. 项目详情 → 「人工校准」区 → 修正当前节点/进度/风险
2. 修正后项目自动**锁定**，AI 不会覆盖你的人工值
3. AI 后续有新判断会进入「待确认建议」，你点「采纳」才生效
4. 每次修正都留痕（变更历史可查），满足审计要求

## 四、常见问题

| 问题 | 处理 |
|---|---|
| 群里发消息看板没反应 | ①应用发布版本了吗 ②tunnel 还开着吗 ③机器人还在群里吗 ④项目绑定该群 chat_id 了吗 |
| AI 建模节点不准 | 文档里补清楚"完成标准"和"责任角色"，重新上传；或模板编辑页手工改 |
| AI 分析报错 | 检查 `.env.local` 的 AI 密钥；把 `FLOWPILOT_AI_PROVIDER` 改成 `mock` 先确认系统本身正常 |
| 干系人没识别 | 让 TA 在项目群里发过消息（AI 会带出真实飞书 ID）；或手动「＋添加」 |
| 改了配置没生效 | 每次改 `.env.local` 后必须重启服务 |
| 端口被占用 | 关掉旧窗口重开；或用 `--server.port=8081` 换端口 |

## 五、多租户（跨公司场景）

对方公司想用你的系统：对方在自己飞书组织创建一套应用（docs/07 第 1.5 章）→
把凭证发你 → 你在配置里加一个租户（`flowpilot.feishu.tenants`）→ 对方群的
消息就进入同一个看板，渠道标签会标注来源组织。
