# FlowPilot 评审演示脚本（5 分钟版）

> 面向评审场景：用最短时间展示「飞书 × AI」真实运行闭环。
> 对应题目要求：飞书负责**读取数据、执行任务、回写结果**；AI 负责**分析、生成、判断**。

## 演示前准备（一次性，约 15 分钟）

1. **部署**：任选一种开箱即用路径（README「快速开始」）：
   - 发行包：GitHub Releases 下载 `flowpilot-v1.0.0.zip` → 解压 → 填 `.env.local` → 启动；
   - 或源码运行：`./scripts/start.sh`。
2. **接入 AI**：`.env.local` 填 `FLOWPILOT_AI_*`（中转站密钥 + 模型名）。
3. **接入飞书**（docs/07 图文步骤）：
   - 飞书开发者后台创建企业自建应用，开通 im:message / im:chat / contact:user.base:readonly 权限；
   - 事件订阅 `im.message.receive_v1`，回调地址填
     `https://<你的公网地址>/api/v1/webhooks/feishu/events`
     （无域名用 `./scripts/tunnel.sh` 内网穿透，脚本会直接打印要填的完整地址）；
   - 发布应用版本（管理员审核）。
4. 数据源管理页点「🔍 检测飞书凭证」→ 显示 ✅ 后，把机器人加入一个项目群，绑定该群 chat_id。

## 演示流程（评审口播对应）

| 时间 | 操作 | 展示的「飞书×AI」闭环 | 对应要求 |
|---|---|---|---|
| 0:00 | 打开看板 | 4 个项目、流程图、进度条、风险标识，说明「数据来自飞书群+邮件多渠道归集」 | 开场 |
| 0:30 | 模板页：上传一份流程文档（或选演示模板） | **AI 生成**：大模型把 Word/PDF 解析为结构化流程模型（节点/完成标准/责任角色/SLA） | AI 分析生成 |
| 1:00 | **在飞书群里发一条消息**："策略已生效，可以开远程了" | **飞书读取数据**：事件回调 3 秒内入库，消息出现在项目详情「最近消息」 | 飞书读取数据 |
| 1:30 | 点「🤖 立即 AI 分析」（或等定时任务） | **AI 判断**：识别当前节点推进、进度百分比、干系人、置信度证据链 | AI 分析判断 |
| 2:00 | 看板刷新 | 流程图节点 ✅/🔄 变化、进度条跳动、风险标红 | AI 结果回写看板 |
| 2:30 | 看 SLA 巡检或手动触发预警 | **飞书执行任务+回写**：系统通过飞书 API 向项目群发消息并 @责任人（"节点超时，请及时跟进"） | 飞书执行任务、回写结果 |
| 3:00 | 干系人卡片点「联系」 | **飞书执行任务**：深链直接唤起飞书与干系人的会话窗口 | 飞书执行任务 |
| 3:30 | 人工修正进度 → 再分析 | AI 结果进入「待确认建议」，不自动覆盖人工值（说明校准机制） | 容错设计 |
| 4:00 | 微信导入/邮件渠道（已配置时演示） | 把微信记录 txt 扔进 watch 目录自动归集，邮件自动匹配项目——多渠道同一 AI 引擎 | 加分项 |

## 评审可能的问题与应答

- **Q：飞书和 AI 是否真实联动？** A：飞书开放平台官方 API 全程参与——事件回调读群消息、im/v1 发消息回写、深链唤起会话；AI 大模型对每条增量消息做结构化识别，两者缺一不可（演示时拔掉任一配置系统即不可用，可见依赖真实存在）。
- **Q：换了场景还能用吗？** A：上传任何新流程文档，AI 自动建模新模板，无需开发。
- **Q：数据安全？** A：数据库 AES-256-GCM 列加密、90 天自动清理、人工校准审计、上传文档不落盘（docs/09）。
- **Q：没有域名怎么上线？** A：内网穿透（tunnel.sh）/ 任意云服务器 Docker 部署（docs/08），发行包零编译。
