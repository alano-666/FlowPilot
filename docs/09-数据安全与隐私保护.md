# FlowPilot 数据安全与隐私保护说明（V1.0）

> 本文档说明 FlowPilot 对「聊天记录、邮件、企业内部流程文档」三类敏感数据的
> 全生命周期保护措施。所有措施已随代码交付并可验证。

## 1. 一句话总结

| 数据 | 去哪了 | 保护方式 |
|---|---|---|
| 上传的业务流程文档（Word/PDF 等） | **不保存原件** | 只在内存中解析，落库的只有 AI 抽取的结构化节点（同样加密） |
| 邮件 | 只采集能归属项目的邮件 | 只拉最近 14 天 + 主题/发件人匹配项目才入库（数据最小化） |
| 密码/密钥 | 密码 BCrypt 单向哈希；各类密钥只走环境变量 | 不入库、不入代码仓库 |

## 2. 已实现的防护措施

### 2.1 数据库列级加密（AES-256-GCM）★核心措施

以下字段在数据库中均为密文（窃取数据库文件也无法读取）：

- 聊天消息：`content`（正文）、`raw_json`（原始报文）
- 流程模板：`nodes_json / branches_json / glossary_json`（企业内部文档的抽取结果）
- 项目模板快照、AI 分析结果、证据摘要、校准前后值、AI 建议
- 干系人联系方式（open_id / userid / 微信号）、用户手机号

**启用方法**（生产必须）：

```bash
# 生成 32 字节随机密钥（Base64）
FLOWPILOT_DATA_ENCRYPTION_KEY=$(openssl rand -base64 32)
export FLOWPILOT_DATA_ENCRYPTION_KEY
```

- 密钥只存在于环境变量（或密钥管理服务），**不入库、不入代码仓库**
- 每次写入使用随机 IV，同一内容两次加密结果不同
- GCM 自带完整性校验：密文被篡改会被检测
- 兼容升级：旧数据明文原样可读，新写入自动加密
- 开发环境未配置密钥时明文存储并打印安全警告（便于调试，生产禁止）

### 2.2 上传文档不落盘（数据最小化）

上传的 Word/PDF/Markdown 原件**只存在于内存解析过程**，系统不保存原件，
只保存 AI 抽取出的结构化流程模型（节点/分支/词库，且已加密）。
即使数据库泄露，攻击者也只能看到流程骨架，看不到企业文档原文。

### 2.3 留存与自动清理

- 原始聊天记录默认 **90 天自动删除**（可配 `flowpilot.data.retention-days`，PRD 7.2）
- AI 结构化摘要/证据保留，用于长期分析
- 微信导入的原文件自动归档到 `watch/processed/`，可定期删除

### 2.4 访问控制

| 层级 | 措施 |
|---|---|
| 认证 | JWT 登录 + BCrypt 密码哈希 + **登录防爆破**（5 次失败锁 5 分钟） |
| 授权 | 三级角色（企业管理者/流程负责人/执行人员），接口级 `@RequireRole` 校验 |
| 审计 | ① 所有写操作记录审计日志（谁/何时/哪个接口）② 人工校准记录前后值对比 ③ 导入记录全程留痕 |

### 2.5 传输与展示安全

- 生产环境强制 HTTPS（部署指南反向代理终结 TLS）
- 手机号等敏感字段 API 输出自动脱敏（138\*\*\*\*5678）
- 邮箱密码建议使用授权码，仅环境变量注入

### 2.6 合规边界（红线）

- **个人微信**：不实现任何 hook/进程注入/本地库解密，只处理主动导出的文件（docs/06）
- **数据采集范围**：只采集绑定群聊 + 能归属项目的邮件（数据最小化，PRD 7.2）
- **大模型调用**：聊天内容会发送给所选 AI 服务商用于分析——选择供应商时注意其隐私条款；敏感度极高的内容建议部署私有化模型（Provider 可插拔，接 Ollama 等本地模型即可不出内网）

## 3. 密钥管理清单（部署时逐项核对）

| 密钥 | 存放位置 | 泄漏后果 | 轮换方式 |
|---|---|---|---|
| JWT 签名密钥 | 环境变量 | 可伪造登录 | 重新生成并重启（全员重新登录） |
| 数据库加密密钥 | 环境变量/密钥服务 | 历史密文可被解密 | 重新生成 → 数据需先解密再重加密（备份后操作） |
| AI API 密钥 | 环境变量 | 盗刷额度 | 在网关/供应商后台重置 |
| 邮箱授权码 | 环境变量 | 读取邮箱 | 邮箱设置中撤销重发 |
| 用户密码 | BCrypt 哈希（库中） | — | 系统设置重置 |

## 4. 事故应对预案

| 事件 | 处置 |
|---|---|
| 数据库文件泄露 | 密文存储保证内容不可读；立即轮换加密密钥与 JWT 密钥 |
| API 密钥泄露 | 供应商后台立即吊销；排查审计日志中的异常调用 |
| 账号被爆破 | 防爆破已限速；检查 `[AUDIT]` 日志定位来源 IP，封禁并重置密码 |
| 数据误删 | 恢复 `data/` 目录备份（部署指南建议每日备份） |
| AI 输出异常 | 人工校准锁定机制兜底，AI 不得自动覆盖人工值 |

## 5. 给使用者的通俗说明

1. **你上传的流程文档，系统不留原件**——AI 读一遍、抽出流程骨架，原件直接丢弃。
2. **聊天记录在数据库里是加密的**——就算有人偷走服务器硬盘，看到的也是一堆乱码。
3. **聊天记录 90 天后自动删除**——系统只需要"最近发生了什么"来跟踪项目，不需要永远存着。
4. **谁能看什么有严格权限**——执行人员只能看，负责人能改，管理员管人；每次修改都留痕可查。
5. **发给 AI 分析是不可避免的一环**——如果你连 AI 服务商都不信任，可以把 AI 换成部署在自己公司内部的模型（支持本地 Ollama 等），数据不出公司。
