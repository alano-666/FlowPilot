### 业务服务清单

| 服务 | 核心职责 |
|---|---|
| `AuthService` / `UserService` | 登录发 Token、用户与角色管理 |
| `TemplateService` | 模板 CRUD、版本快照、发布确认、流程 JSON 校验 |

## 3. 核心流程设计

### 3.1 AI 流程状态识别（PRD 3.3 / 6.2）

```
定时/手动/事件触发
  → 收集项目增量消息（lastAnalyzedAt 水位线之后）
  → 预处理：清洗空消息、按 sentAt 排序、截断到 token 上限
  → 组装上下文：流程模板（节点+完成标准+词库+分支）+ 当前状态 + 增量消息
  → LLM 结构化输出（JSON Schema 严格校验）：
       current_node_key / completed_nodes / progress / risk_status
       evidence[]（message_id、node_key、summary、confidence）
       stakeholders_update[]（角色+实名+联系方式）
       risks[] / suggested_next_action / temp_nodes[]
  → 规则落库：
       · 项目未被人工锁定 → 直接更新，写 analysis_runs + ai_insights
       · 项目已人工锁定 → 结果转入 pending_suggestions，等用户确认
  → 联动通知：节点完成→通知下一节点责任人；SLA 超时→@责任人
```

### 3.2 微信记录自动化导入（PRD 3.2 / 用户补充需求）

```
方式一（API 上传）：POST /api/v1/imports/wechat 上传 TXT/CSV → 格式自动识别 → 解析入库
方式二（文件夹监控·推荐）：把记录文件丢进 data/watch/ → 监控服务秒级发现
  → 解析（支持微信复制导出、CSV 导出、截图(可选OCR)）
  → 按「文件名字段匹配」或「用户指定项目」归属项目
  → 自动触发一次 AI 增量分析
个人微信无官方数据接口，本方案做到「人工只做一次导出动作，其余全自动」，
严禁非官方 hook（详见 docs/06-微信聊天记录自动化方案.md）
```

### 3.3 人工校准优先级（PRD 3.6）

```
人工修正 → 项目 manual_lock=true + calibration_logs 记前后值
AI 分析 → 若 manual_lock：仅生成 pending_suggestions（含强证据），
          用户在看板「确认/驳回」后才生效；绝不自动覆盖
```

### 3.4 通知预警（PRD 3.8）

| 触发器 | 条件 | 动作 |
|---|---|---|
| SLA 巡检（每小时） | 当前节点停留超 sla_hours | 风险标 WARNING，通知责任人 |
| 节点完成（分析后） | 上一节点完成 | 通知下一节点责任人启动 |
| 沟通风险（每次分析） | 关键干系人超期未回复 | 风险提醒 |
| 每日摘要（可配 cron） | — | 推送全量进行中项目摘要 |
| 卡顿判定 | 进度长期无变化 | 风险标 BLOCKED |

## 4. 关键设计决策

1. **Provider 可插拔 LLM**：`flowpilot.ai.provider = mock | anthropic | openai`。
   - `anthropic`：官方 Java SDK，默认模型 `claude-opus-5`，结构化输出走 SDK 类型化 `outputConfig`；
   - `openai`：通用兼容协议（DeepSeek / 通义 / 本地 Ollama 均可），`response_format=json_object`；
   - `mock`：**默认**，无密钥即可演示完整闭环。
2. **AI 分析并发**：线程池 `flowpilot.ai.parallelism`（默认 8，可调至 50 满足 PRD），LLM 调用带超时与一次重试。
3. **增量同步水位线**：`sync_states` 表按渠道记录 lastSyncAt/cursor；消息按 `(channelType, channelId, msgId)` 唯一去重。
4. **模板版本化**：模板每次编辑/发布生成 `template_versions` 快照；项目创建时固化 `templateSnapshotJson`，模板后续变更不影响存量项目。
5. **安全**：密码 BCrypt；JWT 默认 24h 过期；管理接口 `@RequireRole(ADMIN)`；微信/手机号等敏感字段前端脱敏（后端 API 返回已脱敏）。
6. **数据留存**：`flowpilot.data.retention-days`（默认 90）定时清理超期原始消息。
